# Migration Notes — Restructuring for Public Release

This file documents every structural decision made while preparing
the codebase for a public GitHub repository, so nothing changed
silently.

| `analysis/feature_engine_v2.py` | `core/feature_engine.py` | Same. |

## Removed entirely (not carried forward)

- `visualization/` — every file in this folder imported modules that
  do not exist anywhere in the codebase (`analysis.parser`,
  `analysis.classifier_new`, `analysis.feature_engine`). It could not
  have executed. Not a working alternate implementation, just dead code.
- `online_pipeline_v2.py` — a live-capture (scapy) script built
  against a different model artifact (`ids_model_v3.pkl`) and a
  disjoint, ad hoc feature dictionary, disconnected from
  `core/feature_engine.py`. Kept out to avoid implying a working
  real-time detection path exists; see `docs/PROJECT_STATUS.md`
  ("Live/streaming detection path: Missing").
- `analysis/siem_correlation.py`, `analysis/alerting.py`,
  `analysis/threat_scoring.py`, `analysis/classifier_v2.py` — none of
  these were imported by any pipeline (offline or online) in the
  original codebase. Dropped from the public repository as unused
  rather than moved to `experimental/`, since there was no clear
  future integration path documented for them.
  **Note on preservation:** "preserved in local git history" is only
  true if these files exist in a commit that predates the history you
  push to GitHub — a fresh `git init` + first commit (the situation
  here, since the remote currently has no code) has no such history
  to preserve. If you want to keep this code retrievable, either (a)
  keep a local-only branch/archive folder containing these four files
  before your first push, or (b) accept that they are dropped
  entirely and retrievable only from this conversation / the original
  source dump. This repository does not include them in any form.
- `dashboard-ids-1/` (React SOC dashboard) — every page rendered
  hardcoded mock arrays (`const threats = [...]`) rather than reading
  `data/final_soc_output.json`. Excluded rather than published as-is,
  since shipping it unchanged would misrepresent it as a live SOC
  view. Rebuilding it to actually consume the pipeline's JSON output
  is a reasonable follow-up, tracked as a TODO rather than shipped
  half-true.
- `data/evaluation_report.json`, `data/live_results.json`,
  `state/correlated.json` — stale outputs from earlier pipeline
  versions (different model artifact names, incompatible feature
  schema, one showing an uninvestigated perfect-score result). Not
  committed; `data/` now ships empty except for `.gitkeep`, and all
  metrics/output files are regenerated by running the pipeline.
- `.manus-logs/`, `__manus__/`, and the Vite plugins that referenced
  `forge.butterfly-effect.dev` — third-party development-platform
  scaffolding with no functional relationship to AEGIS-HYBRID. Removed.

## Security-relevant behavior changes

1. `ingestion/ingest_api.py` now requires an `X-API-Key` header
   (`INGEST_API_KEY` in `.env`) and refuses to start without one. It
   also rate-limits per client IP and caps its dedup cache size
   (previously an unbounded `set()`).
2. `core/active_response.py` replaces the inline `block_ip_system()`
   call in the original pipeline. It is **disabled by default**, only
   acts on IPs inside an explicit CIDR allowlist, and defaults to
   dry-run (logs instead of executing `iptables`). See `SECURITY.md`.
3. All previously hardcoded filesystem paths (`/opt/logs/cowrie.json`,
   `/var/log/suricata/eve.json`, model/dataset output paths) now come
   from `config/settings.py`, which reads environment variables with
   safe defaults — see `.env.example`.
4. `evaluation/evaluate_system.py` no longer applies the original
   `soft_recall_boost()` nudge to ML probabilities before fusion
   scoring. That function existed only in the evaluation script, not
   in the actual inference path, and inflated reported recall
   relative to what the deployed pipeline would produce.

## What was intentionally left unchanged

- The scoring formulas, weights, thresholds, and decision logic in
  `core/fusion_engine.py`, `core/attack_timeline.py`, and
  `core/apt_campaign_engine.py` were preserved without intentional
  behavioral changes relative to the original prototype — only
  formatting, dead comments, and mojibake (corrupted emoji bytes) were
  cleaned up, and no thresholds or weights were retuned. This has been
  spot-checked, not verified with an automated diff against the
  original scoring outputs; if bit-for-bit parity matters for your
  purposes, run both versions on the same session fixtures and compare.
- The XGBoost hyperparameters and calibration approach in
  `ml/train_model.py` are unchanged from the original.
